## Goal
Fundamentally rebuild the Quran recitation player around a single immutable state machine, one obvious control per action, and immediate reciter/riwayah switching, while removing the confusing queue and duplicated transport/drawer controls.

## Constraints
- Keep `mpv_audio_kit` / `TawaqAudioService`; do not replace the audio engine.
- Preserve adhan alert behavior: the alert pipeline must still be able to suspend/resume recitation.
- UI must be Forui-themed; the custom seek slider is the only allowed non-Forui widget and must reuse Forui tokens.
- App is desktop-first; mobile is not a priority, but layouts must not break on smaller viewports.
- No new runtime dependencies without explicit approval.
- The app is not released, so persisted recitation settings can be reset/re-modeled.

### Chunk 3: Recitation audio session controller
**Scope:** Rewrite `RecitationController` as a thin event pump over the state machine + timeline + audio service.

**Files Changed:**
- Modify: `lib/feature/quran/presentation/providers/recitation_provider.dart`
- Test: `test/feature/quran/presentation/providers/recitation_controller_test.dart`

**Depends On:** Chunk 1, Chunk 2

**Accept When:**
- Controller has no hidden mutable state except stream subscriptions and the current `RecitationTimeline`.
- Audio service subscriptions emit events into the state machine; UI reads `RecitationState`.
- `switchReciter(reciter, moshaf)` immediately loads the current surah/range at the matching position when timing exists, else starts at the beginning.
- `seekTo` clamps to range and snaps to nearest ayah start when timing exists.
- Alert suspend/resume still pauses and resumes recitation.
- Tests pass with a fake `AudioEngine`.

**Complexity:** complex  
*Concurrency primitives:* single `StreamSubscription` per audio stream; no shared mutable state; events are processed sequentially on the UI thread.  
*Lifecycle:* subscriptions are created in `build()` and cancelled in `ref.onDispose`. Alert hooks are re-entrant/idempotent.  
*Error propagation:* audio errors become `AudioError` events; controller surfaces a user-facing error string and transitions to `error` status.

## Decision Log
- **Global transport stays in PageShell** — confirmed; audio remains controllable from any route.
- **mpv_audio_kit is retained** — the rework is state/UI, not engine replacement.
- **Queue removed** — confirmed as out-of-scope/confusing.
- **Pending-edit with accept-and-play** — keeps the safety of preview but removes the extra play click.
- **Repeat scope `selection` / `eachAyah`** — satisfies “per ayah in a range” without inventing a separate queue.
- **Custom continuous seek slider** — Forui `FSlider` segments become unusable for long surahs; a custom slider themed with Forui tokens is acceptable.
- **Persisted settings reset allowed** — app is unreleased, so the recitation settings schema can change freely.

## Risks
| Risk | Likelihood | Mitigation |
|------|------------|------------|
| State-machine transitions miss an audio edge case (seek-before-ready, A-B loop exhaustion, cross-surah boundary) | medium | Exhaustive unit tests; keep `safeSeek` retry logic in the audio service wrapper. |
| Custom slider accessibility on desktop | low | Add keyboard support (arrow keys, Home/End) and semantic value labels. |
| Reciter/riwayah switching at arbitrary positions with mismatched timing | medium | Fall back to start-of-surah when timing is missing; surface a brief toast. |
| Cross-surah range repeat semantics become confusing | medium | Keep range dialog explicit: show global from/to and repeat scope; document behavior in tests. |
| Adhan alert suspend/resume regresses | medium | Port existing suspend/resume events exactly into the state machine and test them. |

Open Questions: None.
